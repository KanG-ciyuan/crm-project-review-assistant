# CRM 储备项目运营复盘助手

## 1. 产品一句话定义

面向销售主管和业务运营人员，将 CRM 导出的储备项目明细表转换为可复核的数据质量问题、经营风险清单、团队经营图表和复盘报告草稿。

## 2. V1 目标与边界

### 目标

- 减少人工复制粘贴、跨表套公式和制作基础图表的重复工作。
- 用固定口径识别数据异常和经营风险，避免遗漏。
- 生成可供人工确认和编辑的周报、月度复盘草稿。

### 不做

- 不直接连接 CRM，不改写 CRM 或原始 Excel 数据。
- 不让 AI 判定业务事实，也不让 AI 自动修正金额、概率或日期。
- 不支持任意 Excel 的零配置导入；V1 仅支持标准模板。
- 不向 AI 发送客户联系人、电话、详细客户名称等敏感信息。

## 3. 用户与使用流程

**默认用户：** 销售主管、业务运营人员。

1. 上传 CRM 导出的标准项目明细 Excel。
2. 确认金额单位与字段映射。
3. 系统在浏览器本地完成字段校验、指标计算和风险标记。
4. 用户查看“数据质量待核实”和“经营风险待跟进”。
5. 用户选择生成周报或月度复盘草稿。
6. AI 基于脱敏后的统计结果和风险标签生成文字报告。
7. 用户确认、编辑后导出 Markdown、PDF 或 Excel。

## 4. V1 标准字段

| 字段 | 类型 | 必填 | 用途 | 校验要求 |
|---|---|---:|---|---|
| 项目名称或项目编号 | 文本 | 是 | 定位、去重 | 不允许为空 |
| 部门 | 文本 | 是 | 团队经营分析 | 不允许为空 |
| 销售经理/负责人 | 文本 | 是 | 人员维度分析 | 不允许为空 |
| 项目状态 | 枚举 | 是 | 区分跟进、签约、丢单 | 必须映射到标准状态 |
| 储备金额 | 数值 | 是 | 金额、风险和规模分析 | 必须为大于 0 的数值 |
| 金额单位 | 枚举 | 是 | 统一金额口径 | 元、万元、亿元三选一 |
| 创建日期 | 日期 | 是 | 储备周期分析 | 可识别为日期 |
| 最近拜访日期 | 日期 | 是 | 跟进停滞风险 | 可识别为日期 |
| 预计签约日期 | 日期 | 是 | 预期逾期风险 | 可识别为日期 |
| 成单概率 | 枚举/数值 | 是 | 项目质量分析 | 映射为 0-100% |
| 行业 | 文本 | 否 | 行业维度分析 | - |
| 区域/省份 | 文本 | 否 | 区域维度分析 | - |
| 项目类型 | 文本 | 否 | 项目类型分析 | - |
| 项目等级 | 枚举 | 否 | 优先级分析 | - |

**金额处理原则：** 上传时必须确认金额单位；系统内部统一换算为“元”计算，页面和报告仍显示用户选择的单位。

## 5. 风险与数据质量规则（V1）

### A. 数据质量待核实

| 规则 | 条件 | 系统结果 | 系统不得做的事 |
|---|---|---|---|
| 必填字段缺失 | 任一必填字段为空 | 标记“字段缺失” | 不补造数据 |
| 金额格式异常 | 金额非数值或小于等于 0 | 标记“金额格式异常” | 不猜测金额 |
| 金额极端异常 | 金额超过用户配置上限；或同一负责人至少有 10 条记录时，金额超过该负责人金额中位数的 10 倍 | 标记“金额需复核” | 不自动改零或改单位 |
| 日期逻辑异常 | 最近拜访日期早于创建日期；预计签约日期早于创建日期 | 标记“日期逻辑异常” | 不自动修改日期 |
| 疑似重复项目 | 项目编号相同；或项目名称、部门、负责人和创建日期同时相同 | 标记“疑似重复报备” | 不自动删除记录 |

### B. 经营风险待跟进

| 规则 | 条件 | 系统结果 |
|---|---|---|
| 跟进停滞 | 状态为跟进中，且最近拜访间隔超过 14 天 | 标记“跟进停滞” |
| 预计签约逾期 | 状态为跟进中，且预计签约日期早于当前日期 | 标记“签约预期失效” |
| 高金额低确定性 | 金额高于当前数据集 75 分位，且成单概率不高于 50% | 标记“高金额低确定性” |
| 长周期储备 | 创建日期距当前日期超过用户配置天数，且仍为跟进中 | 标记“长期储备待复盘” |

### C. V1 可配置阈值

| 配置项 | Demo 默认值 | 说明 |
|---|---:|---|
| 跟进停滞天数 | 14 天 | 超过该天数未拜访的跟进中项目进入风险清单 |
| 长周期储备天数 | 90 天 | 超过该天数仍跟进中的项目进入复盘清单 |
| 高金额判定 | 当前数据集金额 75 分位 | 用于识别高金额低确定性项目 |
| 金额绝对上限 | 10,000 万元 | 仅作为 Demo 初始值，正式使用时由企业确认 |

## 6. 输出结构

### 数据质量待核实

显示异常字段、异常原因、项目标识和“待人工确认”状态。

### 经营风险待跟进

按风险等级展示项目、负责人、金额、风险原因和建议跟进行动。

### 经营复盘

- 项目数量与储备金额概览。
- 部门、销售经理、行业、区域的对比图表。
- 高风险项目和异常数据摘要。
- AI 生成的管理层复盘草稿。

## 7. AI 的职责与约束

AI 只接收：汇总指标、脱敏项目编号、风险等级、风险原因和必要的非敏感维度。

AI 可以：

- 整理经营摘要。
- 将风险清单转换为跟进建议。
- 生成日报、周报或月报草稿。

AI 不可以：

- 更改系统风险等级。
- 宣称数据填写错误或业务事实成立。
- 从未提供的数据中补充客户、金额或项目进展。

## 8. 首次验收标准

使用 30-50 条脱敏模拟项目数据，至少覆盖：正常项目、跟进停滞、签约逾期、高金额低概率、金额异常、缺字段和疑似重复项目。

产品需要能够：

1. 读取标准 Excel 并显示字段校验结果。
2. 正确标记上述 7 类测试情形。
3. 输出数据质量清单、经营风险清单和经营概览。
4. 生成可编辑的 Markdown 复盘草稿。

## 9. 下一步

基于本定义创建一份脱敏模拟数据模板，并逐条验证 V1 规则是否符合实际业务口径；规则确认后再写精简 PRD 和页面原型。
