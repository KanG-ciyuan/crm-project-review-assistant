# CRM 储备项目运营复盘助手 V1 PRD

## 1. 产品目标

将 CRM 导出的标准储备项目明细 Excel，转化为三类可人工复核的结果：

1. 数据质量待核实清单。
2. 经营风险待跟进清单。
3. 可编辑的经营复盘 Markdown 草稿。

目标用户是销售主管与业务运营人员。它解决的是“导出明细后，人工复制字段、套公式、做基础图表、再写复盘”的重复工作；不替代业务判断，也不自动改原始数据。

## 2. V1 范围

### 必须实现

- 上传无密码保护的 `.xlsx` 文件，并选择其中一个工作表。
- 在浏览器本地读取表格，校验标准字段、数据类型和金额单位。
- 按固定规则生成数据质量和经营风险标记。
- 展示基础经营概览、部门/负责人维度汇总和风险分布。
- 基于脱敏汇总数据生成一份管理复盘 Markdown 草稿。
- 导出 Markdown 文件。

### 暂不实现

- 直连 CRM、登录账号、数据库和多人协作。
- 上传任意字段的 Excel 后自动猜测字段含义。
- 在网页中改写或回传原始 Excel 数据。
- 自动修改金额、日期、概率或项目状态。
- PDF、Excel 格式的正式报告导出。
- 自定义字段映射和自定义规则编辑器。

PDF/Excel 导出和字段映射属于 V1.1。先用固定模板跑通真实流程，避免第一版变成无法验证的“大而全上传工具”。

## 3. 输入规范

### 文件要求

- 文件格式：`.xlsx`。
- 不支持加密、密码保护或损坏文件。
- 用户可从工作表列表中选择一张项目明细表进行分析。
- 第一版要求所选工作表的表头与下列字段完全一致；缺少字段时不可开始分析。

### 必填字段

| 字段 | 格式要求 |
|---|---|
| 项目编号 | 文本，非空 |
| 项目名称 | 文本，非空 |
| 部门 | 文本，非空 |
| 销售经理 | 文本，非空 |
| 项目状态 | 跟进中、已签约、已丢单之一 |
| 储备金额 | 大于 0 的数值 |
| 金额单位 | 元、万元、亿元之一 |
| 创建日期 | 可识别日期 |
| 最近拜访日期 | 可识别日期 |
| 预计签约日期 | 可识别日期 |
| 成单概率 | 0-100 的数值 |

### 可选字段

`行业`、`区域/省份`、`项目类型`、`项目等级`。缺失时不阻断分析，只是不展示相应维度的图表。

## 4. 用户流程

### 第一步：上传与校验

用户进入网页，上传 Excel 并选择工作表。网页在本地展示：

- 文件名、工作表名、数据行数。
- 前 5 行预览。
- 必填字段是否完整。
- 无效日期、金额或概率的记录数量。

若缺少必填字段、文件无法读取或没有有效数据行，网页不进入分析，并清楚说明需要修正的内容。

### 第二步：确认分析口径

用户确认以下默认阈值：

- 跟进停滞：超过 14 天未拜访。
- 长周期储备：创建超过 90 天且仍为跟进中。
- 高金额：当前数据集中金额高于 75 分位。
- 金额绝对上限：10,000 万元，仅用于 Demo 的“需复核”提示。

用户可以在本次分析中调整停滞天数、长周期天数和金额绝对上限。调整仅影响当前浏览器会话，不改写源文件。

### 第三步：查看复盘结果

网页生成四个区域：

1. **经营概览**：项目数、总储备金额、跟进中项目数、已签约数、已丢单数、风险项目数。
2. **数据质量待核实**：字段缺失、金额格式异常、金额需复核、日期逻辑异常、疑似重复报备。
3. **经营风险待跟进**：跟进停滞、签约预期失效、高金额低确定性、长期储备待复盘。
4. **分布与对比**：按部门、销售经理汇总；有可选字段时再显示行业、区域汇总。

清单支持按风险类型、部门、销售经理筛选。每条记录显示项目编号、项目名称、负责人、金额、风险原因和“待人工确认/跟进”的状态，不提供“自动修复”按钮。

### 第四步：生成 AI 复盘草稿

用户点击“生成管理复盘草稿”。网页只发送脱敏后的统计值和风险标签，得到可编辑的 Markdown，包含：

- 本期经营概览。
- 数据质量提醒。
- 重点风险项目摘要。
- 分部门或负责人的观察点。
- 建议的下期跟进行动。

报告顶部固定声明：**“本报告基于导入数据和规则标签生成，金额、日期、项目状态及业务结论须由业务人员确认。”**

用户可复制、编辑或下载 Markdown。刷新页面后，本地导入数据和结果不保留。

## 5. 规则定义

### 数据质量待核实

| 规则 | 判定条件 | 输出标签 |
|---|---|---|
| 必填字段缺失 | 任一必填字段为空 | 字段缺失 |
| 金额格式异常 | 金额不是数值或小于等于 0 | 金额格式异常 |
| 金额需复核 | 金额超过用户设置的绝对上限；或同一负责人至少 10 条记录且金额超过其中位数 10 倍 | 金额需复核 |
| 日期逻辑异常 | 最近拜访日期早于创建日期；或预计签约日期早于创建日期 | 日期逻辑异常 |
| 疑似重复报备 | 项目编号相同；或项目名称、部门、销售经理、创建日期均相同 | 疑似重复报备 |

### 经营风险待跟进

| 规则 | 判定条件 | 输出标签 |
|---|---|---|
| 跟进停滞 | 项目状态为跟进中，且距最近拜访日期超过停滞阈值 | 跟进停滞 |
| 签约预期失效 | 项目状态为跟进中，且预计签约日期早于分析当天 | 签约预期失效 |
| 高金额低确定性 | 金额高于全量数据的 75 分位，且成单概率不高于 50% | 高金额低确定性 |
| 长期储备待复盘 | 项目状态为跟进中，且创建日期距分析当天超过长周期阈值 | 长期储备待复盘 |

所有规则的输出都是“待核实/待跟进提示”，不代表系统确认原始记录错误，也不代表项目一定存在真实经营风险。

## 6. 数据与安全边界

### 浏览器本地完成

- Excel 的读取、字段标准化、规则计算、图表汇总和风险清单。
- 原始项目名称、客户相关字段、联系人和电话不得上传到服务端或模型。

### 仅在用户生成报告时发送

网页向后端接口发送最小化的脱敏摘要，例如：项目数量、金额汇总、部门统计、匿名项目编号、风险类型和风险数量。后端保存模型 API Key 并调用大模型；浏览器不保存 API Key。

## 7. 页面结构

| 页面/区域 | 目的 | 关键元素 |
|---|---|---|
| 上传页 | 导入并检查模板 | 文件选择、工作表选择、字段状态、前 5 行预览 |
| 分析概览 | 快速判断整体情况 | KPI、规则阈值、部门与负责人汇总 |
| 待核实与风险清单 | 支持人工处理 | 筛选器、风险标签、项目明细、原因说明 |
| 复盘报告面板 | 生成和修改文字成果 | 生成按钮、Markdown 编辑区、下载按钮 |

## 8. 异常状态

| 场景 | 网页行为 |
|---|---|
| 文件不是 `.xlsx` | 拒绝读取，提示更换标准 Excel 文件 |
| 文件无法解析或有密码 | 提示导出为未加密 `.xlsx` 后重新上传 |
| 缺少必填字段 | 列出缺失表头，阻止进入分析 |
| 存在部分格式错误 | 允许分析，其记录进入“数据质量待核实” |
| 没有有效数据 | 不展示图表或报告生成，提示检查表头和数据行 |
| AI 接口失败 | 保留已完成的本地分析，提示稍后重试，不影响 Markdown 手动编辑 |

## 9. 验收标准

使用脱敏模拟数据文件 `CRM储备项目运营复盘助手-脱敏模拟数据.xlsx` 进行验收。产品应：

1. 成功读取 `项目明细（标准导入）` 工作表并显示 30 条数据。
2. 正确识别 10 条预期风险/质量标签，结果与 `测试预期结果` 工作表一致。
3. 对 P-024 只标记“金额需复核”，不得自动认定金额错误或更改金额。
4. 在未调用 AI 的情况下，完整显示经营概览、质量清单和风险清单。
5. 生成报告时只使用脱敏摘要；报告含固定人工确认声明。
6. 重新刷新网页后，不再显示此前上传的原始数据和分析结果。

## 10. 后续版本判断

V1 跑通并由真实用户试用后，再决定是否进入 V1.1：字段映射、PDF/Excel 导出、规则配置保存、CRM 导出模板适配。任何 CRM 直连都应在有真实客户、权限和明确数据合规要求后再考虑。
