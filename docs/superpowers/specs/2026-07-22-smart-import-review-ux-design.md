# 智能快速导入与审查结果简化交互设计

**日期：** 2026-07-22  
**状态：** 已完成头脑风暴并经用户逐项确认  
**产品：** CRM 储备项目运营复盘助手

## 1. 背景

通用 Excel 适配已经解决了不同企业表头不一致的问题，但当前四步导入向导把系统内部的识别过程全部暴露给用户：确认表头、逐列确认字段、逐值统一口径、再确认分析。正常表格也需要完成大量点击，尤其成单概率为 `0.1` 至 `0.9` 时，需要逐项映射，违背了“简单、上手即用”的产品目标。

分析结果页还存在三个直接影响使用效率的问题：规则标签和原因被挤成窄列；筛选选项选择后菜单不自动关闭；审查状态保存后缺少清晰的闭环反馈。

本设计在不削弱通用 Excel 适配和确定性规则能力的前提下，将默认路径改为“智能快速导入”，并简化筛选、审查和结果阅读方式。

## 2. 设计原则

1. 系统能确定的内容不要求用户确认。
2. 只把无法可靠判断的项目交给用户处理。
3. 正常导入路径只需要“上传 Excel”和“开始分析”两次操作。
4. 页面使用业务语言，不向普通用户暴露字段映射、枚举映射等技术概念。
5. CRM 仍是正式数据源；本工具只负责检查、分析和复盘，不回写 CRM。
6. 本次不接入大模型 API。字段识别、数值换算和规则判断继续使用本地、可解释的确定性逻辑。

## 3. 智能快速导入

### 3.1 默认流程

```text
上传 Excel
→ 系统自动识别工作表、表头、字段、状态、金额单位和概率
→ 展示一句识别结果摘要
→ 用户点击“开始分析”
→ 查看分析结果
```

当识别结果完整且没有冲突时，页面不再展示原四步向导。主区域只显示类似以下信息：

> 已识别 18 个字段，共 236 条项目数据，可以开始分析。

页面保留一个主按钮“开始分析”。“查看识别详情”作为默认收起的次要入口，用于查看已识别字段、忽略字段、规则可执行范围和数据预警，但不要求逐项确认。

### 3.2 只确认系统拿不准的内容

以下情况进入“需要确认”区域：

- 存在两个可能的表头行，系统无法可靠选择。
- 一个源字段可能对应多个标准字段。
- 多个源字段被识别为同一个标准字段。
- 项目状态存在无法识别的非空值。
- 金额单位缺失、混用或无法判断。
- 概率值格式无法转换为百分比。

页面只列出这些不确定项，不展示已经确定的项目。用户处理完全部阻断项后，页面恢复为简短摘要和“开始分析”按钮。

缺少某个非必需字段时不阻止整表分析。系统继续沿用规则能力降级机制：依赖该字段的规则跳过，并在识别详情中说明原因。

### 3.3 表头识别

“确认表头行”不再作为固定第一步。系统默认采用评分最高且无并列冲突的候选表头行。

只有候选结果接近或表格前部包含多行标题、合并单元格等情况时，才展示数据预览，让用户选择真正包含“项目名称、部门、销售经理”等列名的那一行。

### 3.4 字段对应

常见列名继续通过本地别名字典自动对应到统一业务字段。未命中标准字段的列默认保留为自定义字段，不要求用户为每一列选择处理方式。

识别摘要只显示数量，例如：

- 已识别标准字段 15 个。
- 已保留自定义字段 3 个。
- 有 1 个字段需要确认。

用户打开“查看识别详情”后，仍可修改字段对应关系、自定义字段名称或忽略列，以保留通用适配能力。

## 4. 成单概率处理

### 4.1 保留实际百分比

成单概率不再转换为“低概率、中等概率、较高概率、临近签约”等展示分类。统一数据模型保存并展示实际百分比，筛选、明细和报告均使用 `10%`、`20%`、`70%` 等原始业务含义。

“询价类”保留为一种特殊的非数值业务值。

### 4.2 自动换算

系统自动处理常见格式：

| Excel 原值 | 分析中显示 |
|---|---|
| `0.1` | `10%` |
| `0.7` | `70%` |
| `10%` | `10%` |
| `70%` | `70%` |
| `10` | `10%` |
| `70` | `70%` |
| `询价类` | `询价类` |

数值大于 0 且小于 1 时按小数概率换算；大于 1 且不超过 100 时按百分数处理。边界值 `1` 若能从 Excel 单元格百分比格式确认，则显示为 `100%`；无法确认格式时进入一次性确认，避免把 `1%` 和 `100%` 混淆。超出 0 至 100、无法解析或包含冲突格式的值进入“需要确认”。

业务规则仍可在内部按照原有百分比阈值执行，但页面不额外添加低、中、高概率标签，也不要求用户逐个映射 `0.1` 至 `0.9`。

## 5. 审查处理闭环

### 5.1 自动保存与同步

用户修改审查状态或处理说明后立即保存，不设置单独的“保存处理结果”按钮。保存成功后，以下内容在当前页面自动重新汇总：

- 审查状态数量。
- 当前筛选结果。
- 分析清单中的处理状态。
- Markdown 复盘报告中的处理结果。

这次重新汇总只更新人工审查统计和报告，不重新改变规则事实。例如原 Excel 仍显示最近跟进超过 30 天时，“跟进超期”规则标签继续保留，同时展示“已确认业务风险”或其他人工状态。

### 5.2 CRM 整改验证

销售人员继续在原 CRM 中更新跟进记录、预计签约日期和项目状态。管理人员重新导出并上传最新 Excel 后，系统重新执行全部适用规则：

- 已修正的问题不再命中规则。
- 仍未修正的问题继续保留。
- 新出现的问题作为本次新问题展示。

因此，人工审查用于确认结论，重新上传用于验证整改；二者不混为同一个动作。

### 5.3 保存反馈与失败处理

状态选择后界面立即显示新状态。保存成功不弹出打断操作的提示；保存失败时在该项目处理区域显示明确错误，并保留用户刚输入的内容供重试。不得出现界面显示已保存、刷新后实际丢失的情况。

## 6. 筛选交互

点击普通筛选值后立即应用筛选并自动关闭当前下拉菜单。已选条件在筛选区下方显示为可移除标签；需要叠加同一字段的第二个值时，用户重新打开该筛选即可。

同时遵循以下行为：

- 点击“只看”、全选或清空后自动关闭菜单。
- 点击页面其他区域或按 `Esc` 关闭菜单。
- 同一时间最多打开一个筛选菜单。
- 已选数量继续显示在筛选按钮上。
- 金额上下限输入完成并按回车或失去焦点后应用并关闭，避免输入第一个数字时提前关闭。
- 筛选变化后，指标、图表、结果清单和当前筛选报告继续同步变化。

## 7. 分析结果排版

### 7.1 桌面端五列结构

结果表由八列简化为五列：

| 列 | 内容 |
|---|---|
| 项目摘要 | 项目名称为主信息，项目编号和客户名称分行显示 |
| 部门 / 负责人 | 部门和销售经理分行显示 |
| 金额 | 储备金额及单位 |
| 发现的问题 | 规则标签单独一行，完整原因在下一行；多个问题纵向排列 |
| 审查处理 | 审查状态、处理说明和最近历史记录纵向排列 |

“发现的问题”获得表格中最大的可用宽度，标签不得与原因挤在同一行。文字按正常中文语句换行，不允许出现一列一个字的竖排效果。

### 7.2 窄屏结构

当页面宽度不足以稳定展示五列时，每个项目转换为纵向信息块，顺序保持为：项目摘要、负责人和金额、发现的问题、审查处理。信息块之间有明确分隔，但不使用卡片套卡片。

审查控件保持稳定尺寸，状态变化、历史说明和长项目名称不得推动其他项目产生明显布局跳动。

## 8. 数据与组件边界

本次调整保持既有“导入适配、统一数据、规则分析、人工审查、筛选报告”边界，仅改变默认交互和概率模型：

```text
Workbook 读取
→ 自动识别结果（已确定项 + 不确定项）
→ 用户只修正不确定项
→ 统一项目数据（实际概率百分比或询价类）
→ 既有确定性规则分析
→ 筛选后的分析视图
→ 自动保存的人工审查记录
→ 同步更新的复盘报告
```

建议将导入识别结果明确建模为“已确定、需确认、阻断错误”三类，使快速路径和高级修改入口共享同一份判断结果，避免在页面组件中重复推断。

## 9. 测试与验收

### 9.1 导入验收

- 标准样表上传后不出现四步向导，只出现识别摘要和“开始分析”。
- 标准样表从上传到分析最多需要两次主动操作。
- 表头不在第一行时，系统能自动选择明确候选；候选冲突时只要求确认表头。
- 常见别名自动对应；只有冲突字段出现在“需要确认”区域。
- 自定义字段自动保留，并可从识别详情修改或忽略。
- 缺少非必需字段时可以继续分析，并正确说明跳过的规则。

### 9.2 概率验收

- `0.1` 至 `0.9` 自动显示为 `10%` 至 `90%`，不出现九个手工映射控件。
- 已带百分号和 1 至 100 的数值保持正确百分比。
- “询价类”保持特殊值。
- 页面、筛选和报告不显示低、中、高概率分类。
- 只有无法从单元格格式判断含义的 `1` 才进入确认；格式明确的 `1%` 或 `100%` 自动识别，非法概率不静默误判。

### 9.3 审查与筛选验收

- 修改审查状态或说明后立即保存，汇总和报告同步变化。
- 人工确认不会删除原始 Excel 仍然命中的规则问题。
- 重新上传整改后的 Excel 会重新执行规则，已修复问题不再命中。
- 普通筛选值、“只看”、全选和清空操作后菜单自动关闭。
- 已选筛选条件可以通过标签直接移除。

### 9.4 视觉与响应式验收

- 在当前常用桌面宽度下，“规则标签与说明”不再出现一列一个字。
- 桌面端按五列结构显示，窄屏按项目纵向显示。
- 长项目名称、长规则原因和长处理说明不会遮挡相邻内容。
- 使用桌面和移动端截图检查排版，并验证所有交互控件可操作。

## 10. 本次范围外

- 不接入大模型 API，不增加 AI 自动判定。
- 不回写 CRM，不把本工具改成正式数据源。
- 不增加自然语言规则编辑器。
- 不重做现有业务规则和金额阈值。
- 不在本次增加历史趋势、账号权限或多人协作能力。
