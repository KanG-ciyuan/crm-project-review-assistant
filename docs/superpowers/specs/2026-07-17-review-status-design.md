# V0.2 审查处理状态设计

## 目标

在 V0.1 的“发现数据质量问题和经营风险”之后，增加本地的人工审查处理闭环。审查记录在同一浏览器中刷新后仍可保留，并在后续重新导入同一项目时提供历史参考。

## 用户流程

1. 用户上传 Excel 并运行规则分析。
2. 网页按项目编号合并异常标签，一项目一行。
3. 用户为每个异常项目选择处理状态，并填写可选说明。
4. 网页将审查记录保存在浏览器本地，不改写 Excel，也不回写 CRM。
5. 用户重新导入 Excel 时，网页按项目编号匹配此前审查记录。
6. 若关键字段未变化，沿用处理状态和说明；若关键字段变化，保留历史说明但把当前状态重置为“待复核”。
7. Markdown 报告区分未处理项目、已确认数据错误项目、已确认业务风险项目和已忽略项目。

## 状态模型

| 状态 | 含义 | 适用场景 |
|---|---|---|
| 待复核 | 尚未由人工确认 | 新发现的问题，或关键字段发生变化的既有项目 |
| 确认数据错误 | 已确认源数据有误 | 金额单位、金额、日期、概率、重复报备等需要回 CRM 修正 |
| 确认业务风险 | 数据真实但需业务动作 | 跟进停滞、签约预期失效、高金额低确定性等 |
| 已忽略 | 已确认本期不处理 | 误报、已在其他流程处理、无需纳入本期复盘 |

每条状态可填写一段处理说明，例如“已通知销售于 7 月 18 日在 CRM 更新金额”。

## 本地存储与匹配

审查记录保存在浏览器的 `localStorage`，键名按项目编号组织，不依赖账号或服务端数据库。

每个记录保存：项目编号、状态、处理说明、首次审查时间、最后审查时间、关键字段指纹和最近一次项目名称。

关键字段指纹由以下字段的标准化值组成：

- 项目编号
- 储备金额与金额单位
- 项目状态
- 成单概率
- 最近拜访日期
- 预计签约日期
- 创建日期

重新导入时：

- 项目编号相同且指纹相同：保留原处理状态和说明。
- 项目编号相同但指纹不同：保留历史说明和历史状态展示，当前状态重置为“待复核”，并标记“项目数据已更新”。
- 新项目：创建“待复核”记录。
- 本次未出现的历史项目：不显示在当前清单中，但不删除本地记录。

## 页面变化

异常项目表新增两列：

- 审查状态：下拉选择四种状态。
- 处理说明：可编辑短文本。

出现指纹变化时，状态列显示“数据已更新，待复核”。清单顶部增加按审查状态筛选。

## 报告变化

Markdown 报告新增“审查处理进度”章节，分别列出：

- 待复核项目。
- 已确认数据错误项目与处理说明。
- 已确认业务风险项目与处理说明。
- 已忽略项目数量。

报告仍保留固定声明：金额、日期、项目状态及业务结论须由业务人员确认。

## 不做

- 不写回 CRM、Excel 或任何外部系统。
- 不支持多人同步、跨设备同步或账号登录。
- 不自动将状态变化认定为 CRM 已修正。
- 不删除历史审查记录。

## 验收标准

1. 用户选择审查状态和输入说明后刷新页面，记录仍保留。
2. 重新导入关键字段未变化的同一项目，状态与说明保留。
3. 重新导入金额、概率、状态或关键日期变化的同一项目，状态变为“待复核”，并保留此前说明作为历史参考。
4. 同一项目的多个规则标签仍合并在一行。
5. Markdown 报告按审查状态正确区分项目。
6. 原始 Excel 不被网页改写，浏览器不向服务端发送项目数据。
