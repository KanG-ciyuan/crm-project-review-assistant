# CRM 储备项目运营复盘助手 V1 实施计划 / Implementation Plan

> 本文是此前英文实施计划的中英双语版本。代码中的名称、文件路径和命令保持英文，便于实际开发时直接使用。
>
> This is the bilingual version of the earlier implementation plan. Code identifiers, paths, and commands remain in English so they can be used directly during development.

**目标 / Goal：**
构建一个独立的浏览器网页工具：本地读取标准 CRM 储备项目 `.xlsx`，用确定性规则产生待核实/待跟进清单，并生成可编辑的 Markdown 经营复盘。

Build an independent browser tool that reads a standard CRM reserve-project `.xlsx` locally, applies deterministic review rules, and produces an editable Markdown operating review.

**架构 / Architecture：**
在 `work/crm-project-review-assistant` 创建一个轻量的 Vite + React + TypeScript 项目。Excel 解析、字段标准化、规则判断、统计与图表均在用户浏览器内完成。首版报告先用确定性规则生成；后续若接入 AI，仅替换报告生成模块，且只发送脱敏摘要。

Create a lightweight Vite + React + TypeScript project under `work/crm-project-review-assistant`. Workbook parsing, normalization, rule evaluation, aggregations, and charts run in the browser. V1 generates reports deterministically; a later AI integration replaces only the report generator and receives anonymized aggregates only.

**技术栈 / Tech Stack：** Vite、React、TypeScript、Vitest、SheetJS (`xlsx`)、Recharts、Lucide React。

## 二、开发任务 / Development Tasks

### 任务 1：建立独立网页工程 / Task 1: Scaffold the independent app

**要做什么 / What to build**

- 新建 `work/crm-project-review-assistant`，不修改既有 AI 测评网站。
- Create `work/crm-project-review-assistant` without modifying the existing AI-assessment site.
- 使用 Vite、React、TypeScript，并加入构建和测试命令。
- Use Vite, React, and TypeScript with build and test commands.

**完成标准 / Done when**

- 本地能打开空白网页，生产构建无报错。
- The blank app opens locally and the production build succeeds.

### 任务 2：实现可解释的本地规则 / Task 2: Implement explainable local rules

**要做什么 / What to build**

- 先为模拟数据中的 10 条预期标签写测试，再实现规则。
- First write tests for the ten expected labels in the demo workbook, then implement the rules.
- 输出必须包含项目编号、标签、原因、部门、负责人、金额和人工处理状态。
- Each result must include project ID, label, reason, department, owner, amount, and human action status.

**规则 / Rules**

- 数据质量：字段缺失、金额格式异常、金额需复核、日期逻辑异常、疑似重复报备。
- Data quality: missing fields, invalid amount, amount requiring review, invalid date logic, suspected duplicate.
- 经营风险：跟进停滞、签约预期失效、高金额低确定性、长期储备待复盘。
- Business risks: follow-up stagnation, expected-signing overdue, high amount/low certainty, long-reserve review.

**完成标准 / Done when**

- P-024 只能显示“金额需复核”，不得改变源金额或宣称它一定填错。
- P-024 is shown only as “amount requiring review”; the source amount is not changed or declared incorrect.

### 任务 3：本地读取和校验 Excel / Task 3: Parse and validate Excel locally

**要做什么 / What to build**

- 仅接受未加密的 `.xlsx`，允许用户选择工作表。
- Accept only unencrypted `.xlsx` files and let the user choose a worksheet.
- 校验必填表头，并保留空单元格以识别字段缺失。
- Validate required headers and preserve empty cells for missing-value checks.
- 不把原始文件或原始项目行上传到服务端。
- Do not upload the original file or raw project rows to a server.

**完成标准 / Done when**

- 错误文件、加密文件、缺失表头、无有效数据均有明确提示。
- Invalid files, encrypted files, missing headers, and empty datasets all show clear messages.

### 任务 4：上传与分析口径页 / Task 4: Upload and analysis settings

**要做什么 / What to build**

- 展示文件名、工作表、前 5 行预览、字段状态和有效数据行数。
- Show file name, worksheet, first-five-row preview, header status, and valid-row count.
- 提供本次会话的 14 天停滞、90 天长期储备、10,000 万金额上限等参数输入。
- Provide session-only inputs for 14-day stagnation, 90-day long reserve, and a 10,000-wan amount ceiling.

**完成标准 / Done when**

- 模拟数据可选择 `项目明细（标准导入）` 并成功进入分析。
- The demo workbook can select `项目明细（标准导入）` and enter analysis successfully.

### 任务 5：经营概览与风险清单 / Task 5: Dashboard and issue lists

**要做什么 / What to build**

- 显示项目数、总储备金额、跟进中、已签约、已丢单、风险项目六项指标。
- Show six KPIs: project count, total reserve amount, in-progress, signed, lost, and risk projects.
- 展示部门、销售经理汇总；有可选字段时展示行业、区域汇总。
- Show department and sales-manager summaries; show industry and region only when available.
- 风险清单可按标签、部门、负责人筛选，但不提供自动修复、删除或改写数据操作。
- Filter by label, department, and owner; do not offer automatic repair, deletion, or source-data changes.

**完成标准 / Done when**

- 模拟数据中的 10 条预期标签均能被查到。
- All ten expected labels in the demo workbook can be found.

### 任务 6：本地生成复盘与 Markdown 下载 / Task 6: Local report generation and Markdown download

**要做什么 / What to build**

- 初版不依赖大模型，按本地统计和风险清单生成复盘草稿。
- The first version does not depend on an LLM; it generates a draft from local summaries and risk lists.
- 包含经营概览、数据质量提醒、重点风险、下期行动，并提供可编辑文本框和下载。
- Include operating overview, data-quality notes, key risks, next actions, an editable text area, and download.

**固定声明 / Fixed disclaimer**

> 本报告基于导入数据和规则标签生成，金额、日期、项目状态及业务结论须由业务人员确认。
>
> This report is generated from imported data and rule labels. Amounts, dates, project status, and business conclusions must be confirmed by business users.

### 任务 7：视觉与数据边界验收 / Task 7: Visual and privacy verification

**要做什么 / What to verify**

- 桌面端为清晰的运营工具布局；移动端单列排布，表格可横向查看，不遮挡文字。
- Desktop uses a clear operations-tool layout; mobile uses one column and horizontally scrollable tables without text overlap.
- 浏览器本地完成文件读取、规则和图表；刷新后不保留导入数据。
- The browser performs parsing, rules, and charts locally; imported data disappears after refresh.
- 当前版本不发送任何原始项目行；未来 AI 只可接收脱敏汇总。
- The current version sends no raw project rows; a future AI may receive anonymized aggregates only.

## 三、验收顺序 / Acceptance Sequence

1. 上传模拟数据并选择 `项目明细（标准导入）`。
   Upload the demo workbook and select `项目明细（标准导入）`.
2. 查看 30 条记录和前 5 行预览。
   Confirm 30 records and a first-five-row preview.
3. 对照 `测试预期结果`，确认 10 条质量/风险标签。
   Compare against `测试预期结果` and confirm ten quality/risk labels.
4. 检查 P-024 保留原金额且仅提示复核。
   Confirm P-024 retains its source amount and is only marked for review.
5. 下载 Markdown，检查固定人工确认声明。
   Download Markdown and confirm the fixed human-confirmation disclaimer.
6. 刷新页面，确认此前数据不再显示。
   Refresh the page and confirm prior data is no longer shown.

## 四、明确不做 / Explicit Non-goals

- 不直连 CRM，不设置账号，不保存历史数据。
- No CRM connection, account system, or historical-data storage.
- 不接受任意字段的 Excel，不让 AI 猜字段。
- No arbitrary Excel schemas and no AI field guessing.
- 不自动修正金额、日期、概率或项目状态。
- No automatic correction of amounts, dates, probability, or project status.
- 不在 V1 输出 PDF/Excel 正式报告。
- No formal PDF/Excel report export in V1.

## 五、实施后的版本判断 / Version Decision After V1

V1 用模拟数据和一次真实导出文件验证后，再决定是否需要字段映射、PDF/Excel 导出、规则保存或 CRM 模板适配。只有在有真实客户、权限和明确的数据合规要求时，才评估 CRM 直连。

After V1 is validated with the demo workbook and one real export, decide whether field mapping, PDF/Excel export, saved rules, or CRM-template adaptation is worthwhile. Evaluate CRM integration only with a real customer, permissions, and explicit data-compliance requirements.
